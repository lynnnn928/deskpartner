The problem

一个共同空间，让工作持续向前。

聊天窗口适合完成一次任务；持续项目需要一个能够保存上下文、决定和下一步的共同空间。DeskPartner 聚焦于让下一次打开时，工作继续向前。

02 / proof

03 / continuity

随时回来，继续推进

Common questions

关于 DeskPartner 的常见问题。

用几句话了解产品定位、使用方式、数据位置和首次接入。

DeskPartner 适合什么样的用户？

DeskPartner 适合同时使用多个 AI 工具、正在推进持续项目的开发者、研究者和独立工作者。它帮助不同 AI 共享项目上下文、历史决定和工作结果。

DeskPartner 和普通 AI 聊天工具如何配合？

你继续使用熟悉的 AI 工具负责理解与执行，DeskPartner 保存项目背景、工作结果、决定和下一步。多个 AI 可以围绕同一个项目接力工作。

DeskPartner 的数据保存在哪里？

项目、事项、接手说明和审批记录默认保存在 Windows 本机。DeskPartner 支持通过 MCP 和 CLI 连接 AI 助手。

第一次使用需要做什么？

下载安装 DeskPartner，连接一个支持 MCP 或 CLI 的 AI，完成一次接入申请与批准，再让它在真实项目里提交第一项工作。

Start with one assistant

开始接入，先完成一件真实的事。

首次接入的目标很简单：连接一个你已经在用的 AI，让它在一个真实项目里完成第一项工作。

01
下载安装并打开 DeskPartner

Windows 10 / 11。数据默认保存在本机，打开后即可建立本地工作空间。

02
复制 MCP 配置，或使用 CLI

在应用内快速上手页复制当前安装路径；支持 MCP 的 AI 宿主重连后即可发现 DeskPartner。

03
让 AI 先读接入说明，再申请加入

它会说明自己是谁、要读取什么，以及哪些操作需要你的批准。

04
在桌面端批准，再开始第一项工作

批准后，让它读取一个项目并提交一项你能判断是否完成的工作。

升级时的一个提醒：如果安装目录发生变化，请重启已经打开的终端或 Agent；MCP 宿主请使用快速上手页的新配置并重连。保持同一安装目录升级时，原有接入配置可以继续使用。
开发者：查看 CLI / MCP 入口

面向需要自动化接入的用户，DeskPartner 同时提供 CLI 和 MCP。请以安装后的 skill / get_guide 输出作为当前接入说明。

node "$DESKPARTNER_CLI" skill

# MCP 配置示例（路径请以应用内复制结果为准）
{
  "mcpServers": {
    "deskpartner": {
      "command": "node",
      "args": ["C:/Users/<你的用户名>/AppData/Local/Programs/desk-partner/DeskPartner/resources/cli/mcp.cjs"]
    }
  }
}

遇到路径问题时运行 `doctor`，它会说明当前路径是否有效以及可用的后备路径。

Local by default

工作在你的电脑里，决定权在你手里。

DeskPartner 是人和 Agent 共享的本地控制面，数据默认留在你的电脑里。

local

本地保存

项目、事项、接手说明和审批记录默认保存在本机数据库。打开后即可建立本地工作空间，更新检查仅访问 GitHub Releases。

approval

重要动作先问你

Agent 可以执行被允许的工作；修改关键资料、删除或需要确认的动作，可以先进入审批。

open

开源且可检查

代码、版本和数据结构公开。你可以从 GitHub 查看实现、更新记录和接入文档。
