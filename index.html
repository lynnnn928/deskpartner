REAL-WORLD WORKFLOW

当你同时开了三个 AI 会话，进度去了哪？

传统待办软件是给人手点的（AI 看不见），而团队协作软件默认每个协作者都是人类。

真实场景：你有三个 AI 同时在做三个项目——Claude Desktop 在帮你梳理架构、Cursor 在改前端组件、另一个终端 Agent 在跑回归测试。半小时后你切回电脑，十几个聊天窗口滚了上千行：谁做完了？谁卡住了？哪条改动还没验收？下一次开新会话怎么接着干？

01 · 共享本地看板

多 AI 读写同一个本机数据库

你在桌面界面看 7 态看板、审批与项目概览；手下的 AI 通过 MCP 或 CLI 读写同一个本机 SQLite 库，主动领卡、记进展评论、交活候审。

02 · 权责与仓储护栏

AI 提议与交活，你只管拍板

新 AI 首次注册需你在界面点「批准」；AI 新建事项先进「待确认」池；执行方不可自验把任务标为「已完成」（仓储层硬拦截）；删卡与改配置须经你授权。

03 · 项目接手说明

换个 AI 接着干，不用重喂背景

每个项目内置带修订历史与一键回滚的「接手说明（Handoff）」。上一个 AI 交活时更新现状与下一步，下一个 AI 一条命令就能完整接棒。

QUICK START

3 步把你的 AI 助手接进来

安装打开 DeskPartner 后，可直接在主窗口左下角「? → 快速上手」一键复制已自动填好你本机路径的开场提示词，也可以按以下三步手动接入：

STEP 01

将 DeskPartner 加进客户端 MCP 配置

在 Claude Desktop、Cursor、Penguin 等客户端配置文件中加入 deskpartner（可在桌面端「设置 → 系统」直接复制本机路径）。若你的 AI 可直接执行终端命令，也可无需配置 MCP，直接让它运行 node "$DESKPARTNER_CLI" skill。

mcpServers 配置片段 
{
  "mcpServers": {
    "deskpartner": {
      "command": "C:\\Users\\<你的用户名>\\AppData\\Local\\Programs\\desk-partner\\resources\\cli\\mcp.cmd",
      "args": [],
      "env": {
        "DESKPARTNER_AGENT": "agent:claude"
      }
    }
  }
}
STEP 02

发一句话让 AI 自助注册领证

把右侧这段话发给你的 AI 助手。它会自己阅读内置说明书，完成身份注册（agent register）与本地凭据申领（agent credential）。此时它处于待批准状态，还不能往你的数据库写任何内容。

发给 AI 的开场提示词 
请先调用 DeskPartner 的 get_guide 工具（或运行 node "$DESKPARTNER_CLI" skill）阅读接入说明书，用你自己的名字注册身份并申领凭据，然后查看我当前的项目和待办。
STEP 03

在桌面界面点一次「批准」

当 AI 完成注册时，DeskPartner 顶部会弹出提醒横幅，侧边栏「审批」也会亮起角标。点击「批准」后，这个 AI 就可以正式在看板上帮你创建事项、记录进展并交付成果了。

审批通过后的闭环体验
1. AI 提议的新事项进入「待确认」池，由你决定是否转入「待办」； 2. AI 干完活将卡片推至「待验收」并附上四段式收口记录； 3. 你验收满意后点击「完成」—— 执行方自己无法越权标完成。

PRIVACY & DATA

数据存哪与隐私边界

无账号体系、无云端后台，所有项目与协作记录完全留在你自己的电脑里。

LOCAL SQLITE STORAGE

本机数据库存储与自动快照备份

核心数据库默认保存在 %APPDATA%\desk-partner\user.db（可在「设置 → 系统」中一键打开文件夹或迁移目录）。每次数据库结构升级或导入备份前，都会自动生成带时间戳的 SQLite 一致性快照；导出 JSON 备份时自动剥离本地凭据哈希。

ZERO DATA UPLOAD

仅检查更新时访问 GitHub Releases

本地使用统计（Telemetry）仅保存在本机 SQLite 数据库中用于渲染「统计」页图表，可随时关闭或一键清空。应用仅在检查版本更新时访问 GitHub Releases（可在「设置 → 系统 → 自动检查更新」中关闭），不上传任何本地数据。
