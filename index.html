A local workspace for human + AI

让 AI 接着工作，而不是每次从头开始。

DeskPartner 把多个 AI 助手共享的项目背景、历史决定和工作结果放在同一个本地工作空间里。AI 负责执行，你负责批准、验收和决定。

适合谁：同时使用多个 AI 工具、正在推进长期项目的开发者、研究者和独立工作者。

The problem

AI 会做事，但工作仍然会断掉。

聊天窗口适合完成一次任务，却不擅长保存一段持续工作的上下文。DeskPartner 只解决一个核心问题：下一次打开时，工作还能继续。

01 / context

换个 AI，就要重新解释项目

背景散落在不同会话里。新的 Agent 需要重新考古，你也要重复讲一遍已经讲过的内容。

02 / proof

“完成了”不等于真的完成

多个 AI 同时工作时，你需要看见它做了什么、依据是什么，以及结果是否经过真正的验收。

03 / continuity

项目一中断，就不知道从哪里继续

几天后回来、换一个 Agent、或让多个助手接力时，下一步应该清楚地留在项目里。

“助手可以换，工作不要从头开始。”

Three roles, one workspace

不是让 AI 取代你，而是让分工变清楚。

DeskPartner 不替代你正在使用的 AI。它把执行、记录和决定放回各自应该在的位置。

AI 助手 执行者

理解你的意图，读取允许的上下文，执行工作，提交结果和提议。

DeskPartner 共享工作空间

保存项目背景、历史决定、工作状态和交接记录，让不同助手看到同一份事实。

你 决定者与验收者

批准重要动作，判断结果是否达标，决定项目要往哪里走。

Your first win

第一次成功，不是“安装完成”。

真正的第一次价值，是你看到一个 AI 在 DeskPartner 里留下了可理解、可验收、以后还能继续的工作结果。

01

接入一个你已经在用的 AI

通过 MCP 或 CLI 把它连接到本地工作空间。

02

你批准它进入项目

它先申请权限；重要操作不会悄悄发生。

03

它读取背景并提交一项工作

项目说明、历史决定和当前工作都可以按需读取。

04

你看见证据，再批准或验收

你知道它做了什么、没做什么，以及下一步在哪里。

The moment it clicks

下次换一个 Agent，项目仍然在这里。

这就是 DeskPartner 和普通聊天记录、轻量待办清单的区别。

  • 共享项目上下文
  • 可找回的历史决定
  • 清楚的等待、提议和验收状态
  • 本地保存，重要操作由你批准

Inside the workspace

你会在里面看到什么？

不是一个更复杂的聊天窗口，而是一份可以被人和多个 AI 共同继续的工作记录。

项目接手说明：让新的 Agent 先理解背景、决定和当前入口，而不是直接拉取一大堆事项。

Use it for real work

它适合哪些持续工作？

把它放进一个真实项目里，而不是只拿来演示功能。

01 / SOFTWARE

软件项目

开发、测试、审查 Agent 分别工作；你能看见结果是否经过验收，以及下一个 Agent 从哪里继续。

02 / RESEARCH

研究与内容

让不同助手搜集、整理、修改，但把来源、决定和最终确认权留在同一个项目里。

03 / LONG-RUNNING

长期个人项目

准备考试、做产品、整理资料或经营一项计划。隔几天回来，也不用从聊天记录里考古。

A good fit / not for everyone

先判断它是不是你的工具。

✓

适合：你同时使用多个 AI 工具

你已经遇到过上下文丢失、工作交接混乱，或者不知道 AI 到底做没做完。

✓

适合：你有一个会持续数天的项目

你需要保存背景、决定、结果和下一步，而不是只完成一次问答。

—

暂时不适合：只想要轻量待办清单

DeskPartner 的价值在 Agent 协作和工作连续性，不是替代最简单的 Todo 应用。

—

暂时不适合：希望完全零配置

首次使用需要接入一个支持 MCP 或 CLI 的 AI；完成后，后续项目可以复用这份工作空间。

Start with one assistant

开始接入，先完成一件真实的事。

首次接入不是为了学会所有功能。连接一个你已经在用的 AI，让它在一个真实项目里完成第一项工作。

01
下载安装并打开 DeskPartner

Windows 10 / 11。数据默认保存在本机，不需要注册云端账号。

02
复制 MCP 配置，或使用 CLI

在应用内快速上手页复制当前安装路径；支持 MCP 的 AI 宿主重连后即可发现 DeskPartner。

03
让 AI 先读接入说明，再申请加入

它会说明自己是谁、要读取什么，以及哪些操作需要你的批准。

04
在桌面端批准，再开始第一项工作

批准后，让它读取一个项目并提交一项你能判断是否完成的工作。

升级时的一个提醒：如果安装目录发生变化，已经打开的终端或 Agent 需要重启；MCP 宿主可能需要用快速上手页的新配置覆盖旧路径并重连。常规覆盖安装保持同一目录时，通常不需要再次配置。
开发者：查看 CLI / MCP 入口

面向需要自动化接入的用户，DeskPartner 同时提供 CLI 和 MCP。请以安装后的 `skill` / `get_guide` 输出为准，不要复制过时的命令表。

node "$DESKPARTNER_CLI" skill

# MCP 配置示例（路径请以应用内复制结果为准）
{
  "mcpServers": {
    "deskpartner": {
      "command": "node",
      "args": ["C:/Users/<你的用户名>/AppData/Local/Programs/desk-partner/DeskPartner/resources/cli/mcp.cjs"]
    }
  }
}

遇到路径问题时运行 `doctor`，它会说明当前路径是否有效以及可用的后备路径。

Local by default

工作在你的电脑里，决定权在你手里。

DeskPartner 不是云端聊天平台，而是人和 Agent 共享的本地控制面。

local

本地保存

项目、事项、接手说明和审批记录默认保存在本机数据库。无需注册账号，只有检查更新时访问 GitHub Releases。

approval

重要动作先问你

Agent 可以执行被允许的工作；修改关键资料、删除或需要确认的动作，可以先进入审批。

open

开源且可检查

代码、版本和数据结构公开。你可以从 GitHub 查看实现、更新记录和接入文档。
