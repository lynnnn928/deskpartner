THREE CORE QUESTIONS

当你同时开了三个 AI 会话，DeskPartner 替你守住哪三件事？

传统待办软件是给人手点的（AI 看不见），而团队项目软件默认每个协作者都是人类（没有防越权护栏）。

真实场景：你有三个 AI 同时在推项目——Claude Desktop 在梳理架构、Cursor 在改前端组件、终端 Agent 在跑回归测试。半小时后你切回电脑，十几个聊天窗口滚了上千行：谁做完了？谁自己把没测过的活标成了完成？下一次开新会话怎么接着干？

第一问 · 全局掌控

AI 做过什么，不用再翻聊天记录

所有 AI 会话通过 MCP 或 CLI 读写同一个本机 SQLite 库，你在桌面工作台按项目或按 Agent 视角实时查看全局进展。

  • 「我的工作」跨项目聚焦：按项目汇总所有等你拍板或验收的事项。
  • 六合一项目工作台：概览、7 态事项、流转动态、版本归档、本地文档沙箱、全局搜索。
  • 「本次变更」精准核验：验收时直接看本轮交付改了哪些字段与描述追加。
第二问 · 验收与追责

AI 交付的活，不能自己宣布完成

协作规则下沉到 SQLite 仓储层硬拦截（G1–G10），哪怕 AI 编造参数也无法绕过你把任务直接标为「已完成」。

  • 提议与立项分离：AI 新建事项先进「待确认」池，不经你同意不得进入正式待办。
  • 强制留证与禁自验：子任务全部完结、附上四段式收口与验证证据才能报审；执行者不可自验。
  • 授权后服务端代执行：删卡或改设置须经你点「允许」，批准瞬间由主进程直接执行并落审计回执。
第三问 · 跨会话记忆

换个 AI 接手，项目不用从零交代

每个项目内置权威的「项目接手说明（Handoff）」长期记忆层，把背景、当前决定与下一步行动沉淀在数据库里。

  • 50 版修订历史与回滚：每次保存完整留痕，写坏了一键回滚为新修订。
  • 事实快照与过期拦截：AI 提议更新时自动记录版本、schema 与当前主线，审批页并排对比新旧事实。
  • #短号 实时状态联动：接手说明中引用的事项编号自动解析并展示最新状态。

CLOSED-LOOP WORKFLOW

一件事从 AI 提议到验收，再到下一个 AI 接手

每个关键节点都有明确的状态归属与仓储层关口保护，形成完整的本地人机协作闭环。

STEP 01 · 发现与提议 AI 助手

提交「待确认」事项

AI 在巡检代码或执行任务时发现新问题，建卡只能进入「待确认」池（G3 关口拦截），不会擅自污染你的正式待办列表。

STEP 02 · 拍板立项 主用户 → AI

批准转入「待办 / 进行中」

你在看板确认方向后将其转入「待办」；AI 认领卡片进入「进行中」，按需拆解子任务并持续追加进展评论。

STEP 03 · 敏感操作拦截 审批中心

点「允许」后由服务端代执行

若 AI 需要删除旧卡或修改配置，系统自动挂起并生成授权申请；你点「允许」后由主进程立即执行并记录回执，无需 AI 重试。

STEP 04 · 留证报审 AI 助手

附验证证据推至「待验收」

所有子任务完结后（G6），AI 必须填写四段式收口记录与验证证据（G5）才能推入「待验收」，且系统严禁执行者自验（G7/G10）。

STEP 05 · 人工核验 主用户

核对「本次变更」通过或退回

你打开抽屉查看「本次变更（Review Diff）」与验证结果，满意则点「完成」关联版本号，不满意则写明原因退回重做。

STEP 06 · 记忆交棒 下一个 AI

更新接手说明，无缝接力

AI 基于当前事实快照提议更新项目接手说明（Handoff）；经你对比采纳后，下一个 AI 会话一条命令即可读懂全局继续推进。

QUICK START

3 步把你的 AI 助手接进来

安装打开 DeskPartner 后，可直接在主窗口左下角「? → 快速上手」一键复制已自动填好你本机路径的开场提示词，也可以按以下三步手动接入：

STEP 01

将 DeskPartner 加进客户端 MCP 配置

在 Claude Desktop、Cursor、Penguin 等客户端配置文件中加入 deskpartner（可在桌面端「设置 → 系统」直接复制本机路径）。若你的 AI 可直接执行终端命令，也可无需配置 MCP，直接让它运行 node "$DESKPARTNER_CLI" skill。

mcpServers 配置片段 
{
  "mcpServers": {
    "deskpartner": {
      "command": "C:\\Users\\<你的用户名>\\AppData\\Local\\Programs\\desk-partner\\resources\\cli\\mcp.cmd",
      "args": [],
      "env": {
        "DESKPARTNER_AGENT": "agent:claude"
      }
    }
  }
}
STEP 02

发一句话让 AI 自助注册领证

把右侧这段话发给你的 AI 助手。它会自己阅读内置说明书，完成身份注册（agent register）与本地凭据申领（agent credential）。此时它处于待批准状态，还不能往你的数据库写任何内容。

发给 AI 的开场提示词 
请先调用 DeskPartner 的 get_guide 工具（或运行 node "$DESKPARTNER_CLI" skill）阅读接入说明书，用你自己的名字注册身份并申领凭据，然后查看我当前的项目和待办。
STEP 03

在桌面界面点一次「批准」

当 AI 完成注册时，DeskPartner 顶部会弹出提醒横幅，侧边栏「审批」也会亮起角标。点击「批准」后，这个 AI 就可以正式在看板上帮你创建事项、记录进展并交付成果了。

审批通过后的闭环体验
1. AI 提议的新事项进入「待确认」池，由你决定是否转入「待办」； 2. AI 干完活将卡片推至「待验收」并附上四段式收口记录； 3. 你验收满意后点击「完成」—— 执行方自己无法越权标完成。

PRIVACY & DATA

数据存哪与隐私边界

无账号体系、无云端后台，所有项目与协作记录完全留在你自己的电脑里。

LOCAL SQLITE STORAGE

本机数据库存储与自动快照备份

核心数据库默认保存在 %APPDATA%\desk-partner\user.db（可在「设置 → 系统」中一键打开文件夹或迁移目录）。每次数据库结构升级或导入备份前，都会自动生成带时间戳的 SQLite 一致性快照；导出 JSON 备份时自动剥离本地凭据哈希。

ZERO DATA UPLOAD

仅检查更新时访问 GitHub Releases

本地使用统计（Telemetry）仅保存在本机 SQLite 数据库中用于渲染「统计」页图表，可随时关闭或一键清空。应用仅在检查版本更新时访问 GitHub Releases（可在「设置 → 系统 → 自动检查更新」中关闭），不上传任何本地数据。
